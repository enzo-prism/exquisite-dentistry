# Build Workflow Guide

This repository ships a Vite + React front end with image optimization, blog generation, SEO smoke tests, and a standalone static veneers mini site. Use this guide whenever you need to build or verify the project locally or in CI.

## Toolchain Requirements

- **Node.js**: 20+ locally; CI uses 22. Vercel builds with the project-configured Node runtime. Use `nvm` to hop versions quickly when debugging local issues.
- **npm**: ships with Node; lockfile is `package-lock.json`, so avoid `pnpm`/`yarn`.
- **OS packages**: the Sharp-based optimizer needs system libvips; most macOS/Linux installs already include it. If you hit install errors, run `brew install vips` (macOS) or `apt install libvips-dev` (Debian/Ubuntu).

## Daily Development Loop

```sh
npm install          # one-time per machine
npm run dev          # Vite dev server @ http://localhost:8080
```

- Vite auto-picks up `.env` changes; copy `.env.example` if you need `VITE_GSC_VERIFICATION`.
- Hot reload works best when you leave `npm run dev` running and edit via the repo root.

## Release-Ready Build Checklist

| Step | Command | Notes |
| --- | --- | --- |
| 1 | `npm run generate:blog` | Only when files inside `Blog-Content/` change. |
| 2 | `npm run lint` | ESLint (TS + React Hooks). Add `-- --fix` to auto-fix style issues. |
| 3 | `npm run typecheck` | `tsc -p tsconfig.app.json --noEmit`. **Step 4 does not do this** — see below. |
| 4 | `npm run build` | Optimizes assets, builds Vite, then prerenders route HTML and generates SEO/search output in `dist/`. |
| 5 | `npm run check:seo` | Verifies canonical, OG, and JSON-LD tags inside `dist/index.html`. |
| 6 | `npm run preview` | Serves `dist/` on `http://localhost:4173` for smoke checks. |
| 7 | `npm run test:e2e` | Chromium/WebKit Playwright suite; starts its own dev server. Run focused specs when only one flow changed. |
| 8 | `npm run test:redirects` | Requires `npx vercel dev --listen 127.0.0.1:8899 --yes` or `REDIRECT_TEST_BASE` pointed at a Vercel deployment. |

> **`npm run build` never runs `tsc`.** Vite strips TypeScript with esbuild, which is
> transpile-only, so type errors do not fail the build and a green `dist/` says nothing about type
> correctness. `npm run typecheck` is the only gate that catches them — keep it as its own step.
> `tsconfig.app.json` uses `strict: true`; run this gate separately before release.

## Continuous Integration

`.github/workflows/ci.yml` gates PRs into `main` and `staging` (the older `verify-prod` /
`verify-staging` workflows only smoke-test the live site after a deploy). Three parallel jobs:

| Job | Runs |
| --- | --- |
| `lint-and-content` | `lint`, `typecheck`, `test:content`, `test:blog`, veneers archive integrity and route-unit checks |
| `build-and-seo` | `build`, then `check:seo` + `test:seo`, plus the veneers production-preview Chromium specs |
| `e2e` | Playwright on chromium + webkit (boots the dev server itself) |

Two non-obvious requirements in `build-and-seo`: it checks out with `fetch-depth: 0` so
`scripts/generate-file-dates.mjs` can derive real `<lastmod>` dates from history, and it
pre-installs `netlify-cli` because `test:seo` boots `netlify dev` against `dist/` and the
first-run download would otherwise blow past the script's 30s server-wait window.

## Image & Asset Pipeline

- `npm run build` runs the full production pipeline: image optimization, Vite build, static prerender, sitemap generation, search-index generation, and staging SEO pruning. The optimizer writes WebP derivatives into `public/optimized/`, and the build refreshes `src/utils/imageRegistry.json`; avoid committing timestamp-only registry churn and never commit `dist/`.
- The Sharp script skips files that already have an optimized counterpart, so rerunning it is safe but can take a couple minutes on large batches. Keep an eye on git status afterwards—no changes should appear because optimized files live under `public/`.

## Veneers Archive Workflow

`public/veneers/` contains the generated static mini site and its local dependencies. Vite development/preview middleware serves known archived directory documents directly; production serves their built directory indexes. The main prerenderer excludes these routes, so it cannot overwrite `/veneers/index.html` with the former React pillar page. Main-site cost and treatment guides remain React routes because only manifest-listed archive paths cross this boundary.

The shared shell is generated by `scripts/veneers-shell.py` and styled/enhanced by `public/veneers/shell.css` and `shell.js`. Original body markup, decorative hero bands, images, and generated styles are retained. Edit the shell source rather than hand-editing generated page documents. The full `public/veneers/manifest.json` audits pages, assets, integration files, and retained content; its compact `src/constants/legacyVeneersManifest.json` mirror drives routing, sitemap, and search integration.

Ordinary `npm run build` uses the committed archive without fetching the original domain. Regeneration is a separate operation requiring Python 3. The durable capture is `archive-source/veneers/originals.tar.gz`, with its checksum and source records in `archive-source/veneers/provenance.json`; offline generation verifies and unpacks it into ignored `work/veneers-source/`. It reuses original binary assets from `public/veneers/` only after checking their source hashes, while original HTML/API and transformed asset source bytes come from the bundle:

```sh
python3 scripts/archive-veneers.py --offline
npm run test:veneers
npm run build
npm run preview -- --host localhost --port 4173
```

Keep preview running and execute the browser checks in another terminal:

```sh
VENEERS_TEST_ORIGIN=http://localhost:4173 npm run test:veneers -- --browser
npm run test:veneers:shell
```

Offline generation refreshes both manifests and the full-content archive search index and works from a fresh clone after the old domain retires. Use `--source-dir /path/to/capture` to select an explicit capture cache. Omitting `--offline` permits read-only refresh GETs for linked archives and uncached dependencies; it does not replace the immutable base-page/API captures. The archive browser harness checks all routes, retained content, local dependencies, comparison drag, search, contact success/error, skip-link clearance, and menu focus on resize. It asserts zero live Formspree submissions. The separate Playwright preview config runs the shell/navigation and mocked measurement specs in Chromium and WebKit without starting a server; `VENEERS_TEST_ORIGIN` overrides its default `http://localhost:4173` origin. Normal CI keeps the existing `playwright.config.ts` development-server workflow. See [VENEERS_MIGRATION.md](VENEERS_MIGRATION.md) for the migration boundaries.

After release, run `npm run verify:veneers` from the released revision. It compares published document/asset hashes with the local manifest and checks canonical URLs, route redirects, MIME types, missing-file 404s, main-guide coexistence, and sitemap/search entries. Its default origin is production; `VENEERS_VERIFY_ORIGIN` selects another deployed origin. It performs read-only fetches without form or booking actions.

## Manual QA Scenarios

After the automated steps pass, run through the high-impact UX flows below. These catch regressions that lint/build cannot.

1. **Contact Hero CTA**
   - Visit `/contact`, click “Send Us a Message” on desktop + mobile widths.
   - Confirm the viewport centers the *Name* field and focus remains on the form card (hero button uses smooth scrolling logic based on element refs).
2. **Formspree submission**
   - Enter a valid email (format validation now blocks malformed addresses).
   - Submit and ensure the inline success message appears and the Formspree dashboard receives the entry.
   - Try an invalid email (`user@`) to confirm the red helper text displays and submission is blocked.
3. **Map & contact links**
   - Click the address block; it should open `https://maps.app.goo.gl/uZPw5AKARk8HuNh9A` in a new tab.
   - Tap the phone CTA on mobile to ensure `tel:` links still function.
4. **Hero/CTA parity**
   - Run `npm run preview`, load key marketing pages (Home, Services, Testimonials) to verify hero buttons still open the default scheduling link unless overridden.
5. **Cherry floating widget**
   - Run `npx playwright test src/__tests__/cherry-widget.mobile.spec.ts --project=chromium --project=webkit --workers=2 --retries=0`.
   - Confirm the complete Cherry compact copy remains visible and collision-free at 320px through desktop widths.

## Form & Analytics Notes

- Form submissions hit Formspree (`https://formspree.io/f/xkgknpkl`). If you clone this workflow for other forms, you only need to swap the endpoint string and ensure `trackFormSubmission('contact_form')` fires after success.
- `src/utils/googleAdsTracking.ts` is a compatibility helper: it classifies schedule/contact/general CTA intent, mirrors privacy-safe events into GA, and never emits direct Ads conversion labels. Only a confirmed Formspree success becomes the canonical `generate_lead`. Follow `docs/ga4-measurement-plan.md` when restructuring CTAs or forms.
- Archived pages use `public/veneers/measurement.js` to load the isolated entry built from `src/legacy/veneersMeasurement.tsx`. Shared consent UI and observability render inside a shadow root; main CSS stays inside that boundary. Preserve the current consent defaults, host guards, manual GA4 page-view policy (`send_page_view: false`), Vercel/OpenAI opt-in behavior, and sanitized attribution. Retired legacy trackers remain removed.
- The archive form runtime must annotate operational/attribution metadata through the shared lead helpers and call `trackFormSubmission` only after a confirmed, eligible real production success. Never pass field values into analytics. Local simulation, QA/test requests, invalid/failed attempts, and honeypots must not generate acquisition conversions. A local UI success is separate from live provider acceptance and delivery.
- Bridge regressions: `npx playwright test src/__tests__/veneers-measurement.spec.ts --project=chromium --project=webkit` uses the normal dev-server configuration and mocked providers to check consent, isolation, attribution, confirmed/failure/QA outcomes, and local simulation. These fixtures do not send a live lead or establish delivery.

## CI / Automation Tips

- Cache `~/.npm` and `node_modules` between runs to cut `npm install` time.
- Vercel uses `npm run build` from project settings. `npm run build:prod` is currently an alias for the same command.
- Add `npm run lint && npm run build && npm run check:seo` to PR workflows; those three commands surface 90% of issues before reviewers look at UI diffs.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| `sharp` fails to install | Install libvips (`brew install vips` or `apt install libvips-dev`) and rerun `npm install`. |
| ESLint exits with React Hook dependency warnings | Address upstream, or suppress per-file only with a short inline justification. |
| Playwright browser missing | Run `npx playwright install chromium webkit`; CI also installs system dependencies with `--with-deps`. The old Puppeteer script is superseded. |
| Formspree returns 403 | The endpoint rate-limits unknown origins. Ensure your dev build runs on `http://localhost:8080` or configure the Formspree project to trust your domain. |

Keep this document up to date whenever you add new build steps, scripts, or verification tooling so future contributors can follow a single source of truth.

When testing the compiled measurement entry on a local production preview, build with `VITE_OPENAI_ADS_PIXEL_ID=playwright-test-pixel npm run build` before `npm run test:veneers:shell`. This public fixture value is also used by CI with mocked provider transport. The production Vercel build uses its separately configured real identifier.
