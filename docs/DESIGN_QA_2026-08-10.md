# Responsive design QA, August 10, 2026

## Release scope

This release resolves the verified responsive, accessibility, and content defects found in a 14-template audit at mobile, tablet, and desktop widths.

Key changes:

- Added an opaque hero poster and delayed Vimeo reveal so a player failure cannot paint error text through the hero.
- Reworked the tablet footer into a two-column accordion layout to prevent heading, link, and wordmark collisions.
- Removed duplicate and constrained related-content layouts from the blog post and veneer templates.
- Kept floating Cherry and navigation controls clear of hero copy, calls to action, and in-flow booking controls.
- Moved the scheduler directly below the schedule-page introduction on mobile and tablet, with financing details below it.
- Added blog and review pagination, blog images and tag cleanup, slider labels, a centered slider start, and 44-pixel controls.
- Corrected verified copy inconsistencies, accessible names, star-rating semantics, and AA contrast failures.

## Root causes

- Shared media assumed the third-party player would always load successfully.
- Breakpoints preserved desktop column density at 768 pixels.
- Reused sections were mounted in both template and page-level layouts.
- Fixed controls were positioned without accounting for page entry state or nearby actions.
- Several content-heavy grids and feeds lacked explicit responsive and pagination limits.
- Brand colors were evaluated visually but not consistently tested against their final surfaces.

## Prevention controls

- Keep poster-first behavior in `VideoBackground`; reveal remote video only after the Vimeo ready event.
- Keep the footer in its compact layout below the `lg` breakpoint.
- Mount related content once, outside narrow article columns, and preserve `min-width: 0` on link cards.
- Test floating controls at the top, after scroll, around booking actions, and near the footer.
- Run the responsive browser suite after changes to navigation, widgets, page order, feeds, or shared layout.
- Run Axe at mobile, tablet, and desktop widths on the homepage, veneers, testimonials, and contact pages before release.

## Verification evidence

- Production build: passed, with 138 prerendered routes, 136 sitemap URLs, and 138 search-index entries.
- Lint: passed with 0 errors. The repository still reports 18 existing warnings.
- Typecheck, content tests, blog tests, SEO checks, and SEO acceptance tests: passed.
- Browser regression suite: 78 of 78 checks passed in Chromium and WebKit.
- Visual sweep: 42 full-page captures across 14 templates and 3 viewports.
- DOM geometry sweep: one H1 and one footer per page, with zero horizontal overflow and zero entry-state fixed-control collisions in all 42 combinations.
- Axe WCAG 2 A, AA, 2.1 A, 2.1 AA, and 2.2 AA tags: 0 violations across 12 page and viewport checks.

The current Vercel build does not supply `VITE_GSC_VERIFICATION`, so the build logs warn and the live meta tag contains the unresolved placeholder. This is an existing Search Console configuration gap, not a responsive-design failure. Configure the production environment variable before relying on HTML-tag ownership verification.

## Release checklist

1. Run `npm run lint`, `npm run typecheck`, `npm run test:content`, and `npm run test:blog`.
2. Run `npm run build:prod`, `npm run check:seo`, and `npm run test:seo`.
3. Run `npm run test:e2e` for the complete Chromium and WebKit suite.
4. Repeat the 42-capture visual and geometry sweeps.
5. Repeat the 12-check Axe gate.
6. Deploy from `main`, then run `npm run verify:prod` and verify the homepage plus changed routes directly.
